# A：比较口径与引导演示

分支：`kiro/comparison-demo`。这是上一条 Kiro 提示词的延续，已有会话可保留原新分支。先阅读 [公共规则](README.md)。

## 目标

让用户从总览到人物、资源、证据和导出，始终清楚自己比较的是哪个时间范围、哪些人、什么阈值；再通过一次 A→B→C 的实际试验理解如何作出安排。

## 当前代码依据

- `CompareReport` / `affectedVisitors` 使用至少 60 秒变化，默认例子为 12 / 9 / 279。
- `Results.tsx` 的 Insights 按 `delta < 0`、`> 0`、`=== 0` 分组，默认为 66 / 26 / 208。
- 当前 `metrics.ts` 的平均/P90基于全部已到达者；旧 Requirement 40 的 completion 子群定义是仅 completed。
- 当前首次可见差异按同刻事件收敛后的状态计算；旧 Requirement 5 附近仍有按事件位置比较的文字，需要同步语义。
- `App.tsx` 已有 `packingExperiment()`；此次工作是提取、组织并完善既有试验，不得归称重新发明了整个实验或引擎。

## A0：先完成公共浏览器测试准备

独占测试依赖和配置。加入同一套 Playwright、本地命令、`e2e/` 目录规则、与 Vitest 的文件隔离。使用真实生产构建及 `/ghost-rehearsal/` 子路径 smoke test。提供失败截图/trace。

先把这个小增量提交到指向集成分支的 PR，独立 review 后供 B/C/D 同步；再继续本任务。后续 CI 部署门槛由 E 完成。不得让普通 PR 获得 Pages 部署写权限。

## A1：统一比较上下文

形成唯一可复用的上下文/selector，至少表达：

- cutoff 或 final/run-limit；每侧实际统计结束时间。
- 统计人群与样本数。
- 等待变化规则：`at-least-one-minute` 或 `any-change`。
- 两侧方案身份、`inputKey`、`scenarioKey`、`modelVersion`。
- ready / stale / 缺少 final / 不兼容运行等状态。

默认保留至少一分钟规则，提供“任何变化”的明确切换。所有总览人数、名单、直方图、人物推荐和 Insights 复用此选择。边界为：一分钟模式包含 ±60 秒；任何变化模式按正负号区分，零不属于少等或多等；不得先把差值按分钟四舍五入再分类。

两侧均已到达的相同 ID 是配对群体的默认口径。非配对/未到达者的处理要清楚列出，不能在不同入口静默使用不同分母。

切换阈值、方案或统计范围后，已有选中人物若不再属于当前群体，采用明确一致的清理/重新选择行为，防止 UI 跳回旧人物。

## A2：明确等待指标的人群

保留“全部已到达者”为主指标，并提供独立标注的“仅完成者”辅助平均/P90和样本数。不得把未完成者的等待从主指标中悄悄移除。

同一规则用于界面、帮助、示例与导出。无样本显示 null/无数据；提前离开、尚未完成、到达晚于 cutoff、达到 horizon 的情况各有独立期望值。最终统计缺失时明确不可用，不把 cutoff 数据伪装为 final。

更新旧需求冲突及任务映射。保留历史验证记录，追加本轮结果，不将旧的 159 项记录改写成当时已有 263 项。

## A3：完成可发现、可重跑的决策演示

1. 从首次入口或比较总览直接进入演示。
2. 标明 A 原安排、B 替代安排、C 基于 B 的试验关系；当前比较两侧的真实名称一直可见。
3. 总览→完整人群→同一人物旅程→首次差异→相关节点/岗位/资源证据→试验→结果与代价→导出安排。
4. 将 `packingExperiment` 提取到独立纯函数或 feature 模块，界面与测试共用；基于传入方案复制并生成合法唯一 ID，不修改原 A/B。
5. 增加一位资料工作人员及明确岗位，保留原有到达、服务、路线、设备和既有岗位。已有工作者的技能、班次和不可用时间沿用当前规则，并在变化摘要列清楚。
6. 原始例子显示 A 完成 43、B 完成 41；C 完成 72、未完成 218、提前离开 10、工作人员 4。C 对 B 的改善与额外退出/人员成本同时显示，所有值读取实际运行。
7. 引导支持退出、重置与重跑。不要覆盖用户原有活动；只清理本次引导自己创建的临时上下文，复用已有项目/Undo能力或明确创建独立演示活动。
8. 保留用户自由编辑和复杂流程能力。需要注意力引导时使用明确的步骤、选中态和视口定位，支持减少动态效果偏好。

## 必须验证

- ±60 秒、±1 毫秒、零差异，人数与完整名单一致。
- 两侧未到达、仅一侧到达、缺少匹配 ID，处理与说明一致。
- cutoff/final、不同 actual until、缺少 final、stale/不兼容，均不产生错误结论。
- 平均/P90 的 completed 子群与全体已到达者分别用可手算 fixture 验证。
- `side-stream:10` 在原始示例中的首次可见差异仍为 210 秒。
- 默认示例 A/B/C 的完成、未完成、提前离开与资源代价正确；不把等待变短统一叫“改善”。
- 复制 C 前后原 A/B、场景与到达保持不变；重复试验不会产生冲突 ID。
- 真实浏览器完成整条引导及退出/重跑；390×844 与桌面均可到达关键操作。
- 当前 canvas owner、分组选择、保存恢复、模板和过期结果回归继续通过。
